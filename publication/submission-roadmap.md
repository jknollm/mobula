# Submission Roadmap

This roadmap translates the draft package into a submission-ready short software publication.

## Phase 1: Narrative Lock (1-2 days)

1. Finalize target venue and page/word limit.
2. Tighten [manuscript-draft.md](./manuscript-draft.md) to venue structure.
3. Convert contribution claims into testable statements.

Deliverable:

- Venue-constrained v1 manuscript text.

## Phase 2: Evidence and Figures (2-4 days)

1. Produce Figure 1-4 from [figure-plan.md](./figure-plan.md).
2. Run benchmark script and capture latency/interaction stats.
3. Add one baseline comparison workflow (time-to-insight or steps-to-insight).

Deliverable:

- Figure set + quantitative appendix table.

## Phase 3: Reproducibility Pass (1-2 days)

1. Validate all commands/endpoints in [usage-appendix.md](./usage-appendix.md).
2. Record environment details (OS, Python, hardware, commit hash).
3. Ensure clean run from clone to viewer launch.

Deliverable:

- Reproducibility checklist with verified commands.

## Phase 4: Submission Packaging (1 day)

1. Prepare camera-ready text and references.
2. Add archival links (code snapshot, docs, optional demo video).
3. Final proofread focused on claims-evidence alignment.

Deliverable:

- Submission bundle ready for upload.

## Decision Gates

- Gate A: Is the narrative specific enough about the multi-domain problem?
- Gate B: Do figures prove linked-domain interaction clearly?
- Gate C: Can an external reviewer reproduce key workflows quickly?
